# 双端界面统一方案：Element Plus 桌面端 + Vant 移动端

> 阶段交付记录。下列提交、脚本和截图反映成员当时的实现。最终版本、运行命令与证据见[终版审查](./final-review.md)。


> 负责人：江贤松（32605150615）· 分工「Vant 移动端页 + Element Plus 布局统一」
> 目标：两套组件库只是**渲染载体**，双端视觉语言、交互逻辑、业务语义统一，只在布局密度与触控尺寸上适配。
> 对应评分表 C3（UI 组件库）、G1（组件库进阶）、G3（体验细节）。

## 一、核心思路：三层统一 + 一层隔离

```
         ┌──────────────────────────────────────────┐
         │  第 1 层：设计令牌（唯一真相源）          │
         │  tokens.css  →  --brand / --gray / ...   │
         │  同时映射 --el-* 与 --van-* 到同一套令牌  │
         └───────────────┬──────────────────────────┘
                         │ 引用（禁止硬编码视觉数值）
         ┌───────────────▼──────────────────────────┐
         │  第 2 层：共享业务语义                    │
         │  useMenu.js / stores/cart.js             │
         │  StatusTag / PriceTag / FoodCard /        │
         │  OrderStatusFlow / PickupCode / MealSwitch │
         └───────┬──────────────────────┬────────────┘
                 │                      │
   ┌─────────────▼────────┐  ┌──────────▼─────────────┐
   │ 第 3 层：桌面渲染     │  │ 第 3 层：移动渲染       │
   │ Element Plus         │  │ Vant（按需引入）        │
   │ MenuView / CartView  │  │ MobileOrderView        │
   │ OrdersView / Admin…  │  │ 手机壳容器内展示        │
   └──────────────────────┘  └────────────────────────┘
   ┌──────────────────────────────────────────────────┐
   │ 第 4 层：隔离 —— 路由懒加载，Vant 只在移动 chunk  │
   └──────────────────────────────────────────────────┘
```

**一句话回答"怎么做"**：不要试图用同一套组件库横跨两端，而是把"一致"上移到**令牌层和业务语义层**，让 Element Plus 与 Vant 各自渲染同一份数据与规则。

## 二、第 1 层：设计令牌唯一真相源

所有颜色、字号、间距、圆角、阴影、动效只定义在 `web/src/styles/tokens.css`。关键是**把两个组件库的主题变量桥接到同一套令牌**：

```css
:root {
  /* 食堂品牌令牌（唯一真相源） */
  --brand-700: #234b36;
  --radius-md: 10px;
  --dur-base: 200ms;

  /* Element Plus 桥接 */
  --el-color-primary: var(--brand-700);
  --el-border-radius-base: var(--radius-md);
  --el-transition-duration: var(--dur-base);

  /* Vant 桥接：同一个令牌，双端同色 */
  --van-primary-color: var(--brand-700);
  --van-radius-md: var(--radius-md);
  --van-duration-base: 0.2s;
}
```

因此改一处品牌色，两端按钮、标签、弹窗、Toast 同时变化，无需改业务代码。写死的像素级差异（Vant 步进器、Dialog 圆角等）集中在 `styles/overrides.css`，不散落到页面。

**验收口径**：业务代码中不出现硬编码色值/圆角/间距；截图对比双端同语义组件，色值一致。

## 三、第 2 层：共享业务语义（统一的灵魂）

### 1. 共享逻辑 `src/shared/useMenu.js`

餐次（早/午/晚/夜宵）、分类、关键词筛选、售罄判定 `isSoldOut()` 只写一份。桌面 `MenuView` 与移动 `MobileOrderView` 都消费它，所以"午餐有哪些菜""哪些菜售罄"两端判断必然一致。

### 2. 共享状态 `src/stores/cart.js`

点餐车的加减、合计 `total`、按档口分组 `byStall`、下单载荷 `payload()` 全部集中。`persist` 打开后刷新不丢。两端操作同一份状态——在桌面加的菜，切到移动端点餐页依然存在。

### 3. 共享业务组件 `src/components/ui/`

| 组件 | 统一的语义 |
| --- | --- |
| `StatusTag` | 招牌/新品/素食/清真/售罄/余量少，颜色与文案绑定 |
| `PriceTag` | 符号+整数+小数分字重，原价/折扣统一格式 |
| `FoodCard` | 4:3 图片、状态角标、售罄灰度遮罩（颜色+文字+图标三重标识） |
| `OrderStatusFlow` | 待支付→待备餐→待取餐→已完成；桌面横向、移动纵向 |
| `PickupCode` | 大字号等宽取餐码 + 窗口 + 预计时间 |
| `MealSwitch` | 餐次切换，移动端 44px 触控 |

组件只负责"信息结构与语义"，布局密度靠外层容器（`@media (max-width:680px)`）适配。

## 四、第 3 层：各自渲染，视觉同款

- **桌面 Element Plus**：`MenuView`（餐次 + 分类 chip + 搜索 + 卡片网格 + 悬浮结算条）、`CartView`（Table 式明细 + 下单 Dialog）、`OrdersView`（状态流 + 取餐码）、`DishDetailView`（动态路由 `:id`）、`AdminDishesView`（Table + Dialog 增删改，满足 T4 的 Table 硬指标）。
- **移动 Vant**：`MobileOrderView` 在**手机壳容器**（`PhoneFrame`）内展示，`van-tabs` 分期/订单、`van-search`、`van-stepper` 增减、`van-dialog` + `van-field` 下单、`van-submit-bar` 风格的底部结算栏、`showToast` 函数式反馈（G1 加分）。

两端共用同一套 `order.css` 视觉语言（hero 横幅、区块标题、加号按钮、数量步进器、结算条），所以即使一个用 el-button、一个用 van-button，看起来仍是同一产品。

## 五、第 4 层：隔离与按需加载（工程加分）

Vant **不在 `main.js` 全局注册**，而是在 `MobileOrderView.vue` 页面组件内按需引入：

```js
import { Tabs, Tab, Search, Stepper, Button, Dialog, Field, Tag, showToast } from 'vant'
import 'vant/es/stepper/style' // 只打包用到的组件样式
```

配合路由的 `() => import('@/views/mobile/MobileOrderView.vue')` 懒加载，构建产物中 Vant 只进入 `MobileOrderView` 独立 chunk：

```
dist/assets/MobileOrderView-*.js    62.59 kB   ← Vant 组件只在这里
dist/assets/MobileOrderView-*.css   98.46 kB   ← Vant 样式只在这里
dist/assets/index-*.js             242.45 kB   ← 桌面主包不含 Vant
```

**结论**：桌面端用户不会下载任何 Vant 代码；移动端页面独立加载。这实现了方案中"双端独立加载、从根源杜绝样式冲突与体积冗余"的要求。

## 六、落地顺序（可复用清单）

1. 固化设计令牌，把 `--el-*` 与 `--van-*` 全量映射到品牌令牌。
2. 组件差异修正集中在 `overrides.css`，禁止散落业务页。
3. 抽取共享逻辑 `useMenu` 与共享仓库 `cart`。
4. 封装业务组件，语义与视觉绑定，不依赖具体组件库。
5. 桌面用 Element Plus 搭页面，移动用 Vant 搭页面，共用上述资产。
6. 移动端在页面内按需引入 Vant，路由懒加载实现产物隔离。
7. 无障碍收尾：对比度达标、状态颜色+文字+图标三重标识、触控 ≥44px、减少动画偏好支持。

### 实测中发现并修复的 3 个真实 Bug
1. **餐次切换对订单无效**：`meal` 未同步到 `cart.meal`，下单永远传午餐。双端均加 `watch(meal → cart.setMeal)` 修复。
2. **移动端 stepper 首次加菜无效**：`onStep` 用了 `setQty`（只对新菜无效），改为不存在时走 `cart.add`。
3. **移动端"招牌推荐"金刚区只切页不筛选**：补齐 `keyword='招牌'`，与桌面一致；并隐藏确认弹窗里冗余的 Vant 默认"确认"按钮（点了不下单，易误导）。

## 十一、答辩聚焦：代码瘦身 + 讲解路线

针对"只讲自己这一部分、代码要少又好讲"的诉求，做了一次**结构瘦身（功能零改动）**：

| 文件 | 改造前 | 改造后 | 说明 |
| --- | --- | --- | --- |
| `web/src/views/mobile/MobileOrderView.vue` | 838 行 | **391 行** | 446 行 scoped 样式整体抽出，组件只剩「逻辑 + 模板」 |
| `web/src/styles/mobile.css` | — | 456 行 | 承接抽出的样式，成为全局样式层的一员 |

**为什么这样改更好讲：**
- 讲组件时不用再念几百行 CSS，一页之内讲清「Vant 按需引入 → 共享 useMenu/cart → 模板渲染 → 下单流程」。
- 样式统一在 `styles/` 层讲一次即可：`tokens.css`（令牌）→ `overrides.css`（双端组件库桥接）→ `order.css`/`mobile.css`（页面视觉）。这正对应方案「样式分层架构」的评分点。
- 类名统一 `m-` / `mobile-` 前缀，是天然命名空间，全局样式不会污染其他页面。
- `mobile.css` 由 `MobileOrderView.vue` 内部 `import`，仍随移动端 chunk 按需加载（构建实测 49KB），桌面产物不含 —— **双端隔离不受影响**。

**踩坑记录（答辩可讲）：** scoped 里的 `:deep(.phone-frame)` 编译后带 `data-v` 属性，特异性 (0,2,0)；改成全局普通选择器后降到 (0,1,0)，被 PhoneFrame 组件自身样式盖过，导致窄屏手机壳边框没隐藏。修复方式是加父级 + 双重类名提到 (0,3,0)，并限定在 `@media (max-width:680px)` 内，桌面预览页不受影响。这个例子正好能说明「理解作用域与特异性」的工程质量意识。

### 建议的答辩讲解顺序（5-8 分钟）
1. **设计令牌**（`tokens.css`）：唯一真相源，`--el-*` / `--van-*` 双端映射 —— 讲「统一怎么做到的根」。
2. **组件桥接层**（`overrides.css`）：把两个组件库的变量/细节覆盖到同一套视觉 —— 讲「抹平原生差异」。
3. **共享业务组件**（`QuickEntries` / `MobileTabBar` / `FoodCard` / `PriceTag` 等）：纯展示 + emit，不依赖组件库 —— 讲「业务语义统一、组件库只是载体」。
4. **Vant 移动页**（`MobileOrderView.vue` 391 行）：按需引入 + 共享逻辑 + 底部导航 + 下单闭环 —— 讲「我这一部分的核心代码」。
5. **收尾**：双端产物隔离（构建截图 + E2E 43/43）—— 讲「可验证的满分证据」。

复验：`npm run build` 通过、`npm test` 18/18、`e2e-buttons.mjs` 43/43、截图重拍后窄屏铺满 / 桌面手机壳完整。

### 发现并修复的 Bug（管理员专属，此前 E2E 因权限拦截从未渲染到该页）

- **样式统一**：学生页与管理员页共用同一套令牌与覆盖层；实测同一 hero 在两种角色下 `backgroundImage` 计算值完全一致。
