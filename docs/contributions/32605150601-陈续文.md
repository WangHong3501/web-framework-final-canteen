### 2. json-server 服务入口与数据接口（`web/server/index.cjs`）

原先由 json-server 路由兜底，存在“任意字段可写、商家可改其他档口、错误格式不统一”的问题。本次改为显式路由 + 统一校验：

- **统一响应**：成功返回资源，失败统一 `{ message, code, fields? }`；`Cache-Control: no-store`。
- **资源边界**：`/users`、`/db` 一律 403；未知资源 404；档口只读，任何写操作 403。
- **菜品**：登录可读，支持 `stallId/stall/meal/category/status/q` 过滤，非法枚举 422；商家只能新增/修改/删除自己 `stallId` 的菜品；字段白名单 + 类型/长度/金额/枚举/引用校验；`id/stall/stallId/rating/sales` 由服务端托管，提交值不落库；未知字段 422 并返回 `fields`。
- **订单**：学生只能看本人、商家可看全部；学生查他人订单返回 404，不泄露存在性；下单只接受 `items/remark/meal/total/stallId`，其中 `total/stallId` 被忽略并由服务端重算；明细只允许 `dishId/qty`，数量 1–20，重复菜品拒绝，售罄拒绝，跨档口拒绝；服务端生成订单号、4 位取餐码、窗口、预计时间，初始状态 `preparing`；商家只能推进本档口订单，学生只能 `ready → completed` 确认。
- **错误处理**：非法 JSON 400 `INVALID_JSON`、超大请求 413、未知字段/枚举/状态 422、越权 403、不存在 404、不支持方法 405、未预期异常 500，且不向前端返回堆栈。

### 3. Axios 统一封装与异常归一（`web/src/api/http.js`、`web/src/api/errors.js`）

- 唯一 Axios 实例：`baseURL` 默认 `/api`，`timeout` 默认 10s、可用 `VITE_API_TIMEOUT` 配置并限制 1–60s。
- 请求自动带 Bearer token（登录接口除外）；全局 `requestState.pending` 计数，成功/失败都归零；导出 `pendingCount`、`isRequesting`、`resetRequestState`。
- 401 且非登录接口派发 `shiguang:unauthorized`，不改变原有页面监听方式。
- `normalizeError` 按“取消 → 超时 → 断网 → HTTP 状态”顺序归一，返回 `{ kind, status, code, message }`；`requestMessage` 保持原导入路径兼容，页面无需批量改 import。
- 区分 `timeout/network/auth/forbidden/not-found/validation/server` 等类型，解决原先“所有无响应都叫网络断开”的误判。
