## 本次实际改动（2026-11-21）

### 1. 点餐车金额统一用整数分

文件：`web/src/stores/cart.js`

- 购物车条目新增 `priceCents`（分，整数），新增 `totalCents`、`byStall[].subtotalCents`。
- 展示用的 `total`、`subtotal` 只在最后一步除以 100，加、减、乘都在整数上做。
- `add()`：元转分用 `Math.round(price * 100)`；同一菜品重复加入只加数量，上限 20 份，并按菜单最新价格更新。
- `setQty()`：非整数直接忽略，小于 1 才移除；`decrease()` 减到 0 自动移除。
- `persist` 仍然只存 `items` 和 `meal`，新增 `afterHydrate` 调用 `migrate()`，把旧版持久化的 `price`（元）迁成 `priceCents`（分），刷新后不会因为字段改名丢购物车。
- `payload()` 仍然只提交 `dishId` 和 `qty`，价格由服务端重新核算。

展示层只改了自己负责的 `web/src/views/order/CartView.vue`。`views/mobile/MobileOrderView.vue` 是江贤松的文件，没有动；为了不破坏它原来的 `item.price * item.qty` 展示，购物车条目保留了一个只读的 `price`（= `priceCents / 100`）兼容字段，金额计算仍然只读 `priceCents`。

### 2. 购物车单元测试

文件：`web/tests/unit/cart.test.js`（6 条）

覆盖：0.1 + 0.2 的浮点误差、重复加菜与 20 份上限、减少/改数量/移除/清空、按档口分组小计、下单载荷、旧持久化数据迁移。

### 3. 构建优化

文件：`web/vite.config.js`

- 增加 `build.rollupOptions.output.manualChunks`，把 Element Plus、Vant、Vue 全家桶、Axios、GSAP、图标库分别拆成独立 chunk。
- 目的：业务代码改动时第三方库的 hash 不变，浏览器可以继续用缓存；入口 chunk 从 192.19 kB 降到 15.14 kB。
- 总体积基本不变（1712.4 kB → 1709.7 kB），JS 从 751.4 kB 降到 748.5 kB，构建耗时在 0.6–0.7 s 之间波动；这次优化的主要收益是入口变小和第三方库可缓存，不是构建速度。

### 手动路径

- 菜单加菜 → 刷新页面 → 数量和合计还在。
- 0.1 元 + 0.2 元两件菜，合计显示 0.30，不出现 0.30000000000000004。
- 同一菜品连续加，最多 20 份；减到 0 自动从购物车移除。
- 提交订单成功后购物车清空并跳到订单详情；连续点击只发一次请求（`submitting` 锁）。
- 学生账号只能看到自己的订单；商家只能推进本档口订单，状态按 `pending → preparing → ready → completed` 走。

## 答辩讲解入口

1. 为什么金额要用分：浮点 `0.1 + 0.2` 不等于 `0.3`，订单金额不能靠最后 `toFixed` 兜底。
2. `persist` 的 `pick` 和 `afterHydrate`：只持久化业务字段，旧数据在恢复时迁移。
3. `manualChunks` 的取舍：总体积几乎不变，但入口变小、第三方库可长期缓存。
4. 订单隔离和状态流转在服务端校验，前端只负责展示和触发，不能靠页面下拉框伪造身份。
