# 商家经营概览（G5-14）

## 功能定位

在原有「订单工作台」和「档口管理」之外，为商家补上经营视角：不用逐笔翻订单，也能一眼看到今天的订单量、营业额、客单价和进行中订单，并及时发现售罄菜品。

参照美团/饿了么商家版的信息组织方式，但只保留与校园食堂自提场景直接相关的能力；优惠券、退款、配送、评价等会引入额外状态机和价格逻辑的模块不在本次范围内。

## 入口与权限

- 路由：`/#/admin/overview`
- 权限：`requiresAuth + roles: ['merchant']`
- 学生访问会被路由守卫重定向到 `/forbidden`
- 商家登录后，在个人中心侧栏可见「经营概览」「档口管理」两个入口；顶部导航的「我的订单」显示为「订单工作台」

## 指标口径

| 指标 | 口径 |
| --- | --- |
| 今日订单 | 本地日期为今天，且状态不是「已退款」的订单数 |
| 今日营业额 | 上述有效订单的 `total` 合计 |
| 客单价 | 今日营业额 ÷ 今日有效订单数 |
| 进行中订单 | 全部订单中状态为「备餐中」「待取餐」的笔数 |
| 热销 TOP5 | 优先按今日有效订单里的菜品销量聚合；今日无订单时，回退到菜品自身的历史销量作为参考，并明确标注 |
| 订单状态分布 | 当前全部订单的状态占比，不按日期筛选 |
| 售罄提醒 | 本档口 `status === 'danger'` 或 `soldOut` 的菜品 |

所有数据均来自现有 `GET /orders` 与 `GET /dishes` 只读接口；不新增后端接口，不改动核价、库存或订单状态机。

## 答辩话术

> 商家端在订单处理和菜品管理之外，增加了经营概览。它复用现有订单和菜品接口，做只读聚合，展示今日订单、营业额、客单价、进行中订单、热销菜品和售罄提醒。这样老师第一眼看到的是商家经营工作台，而不只是两个管理列表。我们没有引入优惠券、退款和配送，是因为它们会牵动价格与状态机，和校园食堂自提的核心场景弱相关。
