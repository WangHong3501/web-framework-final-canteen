# 部署说明（32605150622 李岷鳌）

本文是食堂项目的静态前端 + Node API 部署方案。前端是 Vite 打包后的 `web/dist`，接口仍是仓库里的 `web/server/index.cjs`（json-server + 会话中间件），所以线上不能只传一个静态目录，必须同时有一个常驻的 Node 进程。

## 1. 环境

- Node.js `^20.19.0 || >=22.12.0`（终版复核用 22.23.2）
- npm（终版复核用 10.9.8）
- Nginx（可选，但推荐；也可以直接用 Node 托管静态文件，但缓存和反向代理要自己写）

## 2. 构建

在仓库根目录：

```cmd
cd web
npm ci
npm run build
```

产物在 `web/dist`。构建成功后入口文件是 `dist/index.html`，资源在 `dist/assets`。

成员阶段构建数据（2026-11-21，本机）：

- 3605 个模块，构建约 0.7 s
- 入口 JS 15.14 kB（gzip 6.13 kB）
- JS 合计 748.5 kB，CSS 合计 285.1 kB，产物体积约 1709.7 kB
- 第三方库已按 `vendor-vue`、`vendor-element`、`vendor-vant`、`vendor-axios`、`vendor-gsap`、`vendor-icons` 拆分

## 3. 启动 API

API 默认监听 3001 端口，运行数据写在 `web/.local/`（已加入 `.gitignore`），不要把这个目录提交或暴露到公网。

```cmd
cd web
node server/index.cjs
```

生产环境建议用 pm2 或 systemd 守护：

```bash
cd /opt/shiguang/web
pm2 start server/index.cjs --name shiguang-api
pm2 save
```

注意：会话目前存在 Node 进程内存里，**重启 API 后旧会话失效，需要重新登录**；`.local/` 里的用户资料和密码散列会保留。

## 4. Nginx 配置

把 `deploy/nginx.conf` 复制到 Nginx 的 `conf.d/` 或 `sites-available/`，改两个地方：

- `root` 指向 `web/dist` 的实际路径
- `proxy_pass` 指向 API 的实际地址和端口

示例已经包含：

- `/api/` 反向代理到 `127.0.0.1:3001/`，并去掉 `/api` 前缀
- `index.html` 不缓存，带 hash 的静态资源缓存 30 天
- `try_files` 兜底到 `index.html`（项目用 hash 路由，正常访问不会走到这一条，但直接访问子路径时需要）

改完执行：

```bash
nginx -t
nginx -s reload
```

## 6. 当前限制

- 课程接口是本地 json-server，不是云数据库；线上地址只能证明静态页面和 API 反代可用，不能当成生产级系统。
- 前端没有单独的 `.env.production`，默认请求同源 `/api`；如果 API 放在别的域名，需要设置 `VITE_API_BASE_URL` 并处理跨域。
- 终版 `npm run test:preview` 的六个页面通过 axe 自动检查。实体手机触控及公网速度需要部署后补验。

## 终版同源部署入口

也可以用一个 Node 进程提供静态前端和 `/api`。在 `web` 执行 `npm ci`、`npm run build`、`npm start`，浏览器打开 `http://127.0.0.1:8080/#/login`。`npm run test:production` 使用相同的启动模块和隔离数据库，验证包含取餐与评价的实际流程。

部署时使用支持常驻 Node 和持久卷的主机，设置 `PORT`、`HOST`（容器内可设为 `0.0.0.0`）和 `DB_FILE`（挂载卷下的文件路径）。将外部 HTTPS 请求反向代理到该进程，保留卷内的订单和账号散列。使用静态平台单独托管 `dist` 时，构建前配置 `VITE_API_BASE_URL` 指向实际 HTTPS API。公网地址和实机验收待托管目标确定后登记。

### 按课程 T7 使用 Netlify 静态托管

1. 在支持常驻 Node 与持久卷的主机启动上述生产服务。设置 `HOST=0.0.0.0`、平台分配的 `PORT`、持久卷上的 `DB_FILE`。用该服务的 HTTPS 地址访问 `/api/health`。
2. Netlify 关联本仓库的 `main`。根目录 [netlify.toml](../netlify.toml) 已指定 `web`、构建命令和 `dist`。在平台的构建环境中把 `VITE_API_BASE_URL` 设置为上一步完整的 HTTPS API 地址（含 `/api`）；修改后重新构建。
3. 在静态站点刷新 `/#/menu` 与 `/#/order/订单号`，核对图片、认证和订单数据。用两次独立登录走完学生下单、商家通知、学生取餐，再用实体手机移动网络复验。将实际站点、API 健康地址及日期写回 README。静态平台的构建参数只包含公开 API 地址。
