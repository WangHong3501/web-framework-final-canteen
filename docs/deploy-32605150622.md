# 部署说明（32605150622 李岷鳌）

本文是食堂项目的静态前端 + Node API 部署方案。前端是 Vite 打包后的 `web/dist`，接口仍是仓库里的 `web/server/index.cjs`（json-server + 会话中间件），所以线上不能只传一个静态目录，必须同时有一个常驻的 Node 进程。

## 1. 环境

- Node.js `^20.19.0 || >=22.12.0`（本机验证用 24.19.0）
- npm（本机 11.17.0）
- Nginx（可选，但推荐；也可以直接用 Node 托管静态文件，但缓存和反向代理要自己写）

## 2. 构建

在仓库根目录：

```cmd
cd web
npm ci
npm run build
```

产物在 `web/dist`。构建成功后入口文件是 `dist/index.html`，资源在 `dist/assets`。

当前构建数据（2026-11-21，本机）：

- 3605 个模块，构建约 0.7 s
- 入口 JS 15.14 kB（gzip 6.13 kB）
- JS 合计 748.5 kB，CSS 合计 285.1 kB，产物体积约 1709.7 kB
- 第三方库已按 `vendor-vue`、`vendor-element`、`vendor-vant`、`vendor-axios`、`vendor-gsap`、`vendor-icons` 拆分

## 3. 启动 API

API 默认监听 3001 端口，运行数据写在 `web/.local/`（已加入 `.gitignore`），不要把这个目录提交或暴露到公网。

```cmd
cd web
node server/index.cjs
```

生产环境建议用 pm2 或 systemd 守护：

```bash
cd /opt/shiguang/web
pm2 start server/index.cjs --name shiguang-api
pm2 save
```

注意：会话目前存在 Node 进程内存里，**重启 API 后旧会话失效，需要重新登录**；`.local/` 里的用户资料和密码散列会保留。

## 4. Nginx 配置

把 `deploy/nginx.conf` 复制到 Nginx 的 `conf.d/` 或 `sites-available/`，改两个地方：

- `root` 指向 `web/dist` 的实际路径
- `proxy_pass` 指向 API 的实际地址和端口

示例已经包含：

- `/api/` 反向代理到 `127.0.0.1:3001/`，并去掉 `/api` 前缀
- `index.html` 不缓存，带 hash 的静态资源缓存 30 天
- `try_files` 兜底到 `index.html`（项目用 hash 路由，正常访问不会走到这一条，但直接访问子路径时需要）

改完执行：

```bash
nginx -t
nginx -s reload
```

## 6. 当前限制

- 课程接口是本地 json-server，不是云数据库；线上地址只能证明静态页面和 API 反代可用，不能当成生产级系统。
- 前端没有单独的 `.env.production`，默认请求同源 `/api`；如果 API 放在别的域名，需要设置 `VITE_API_BASE_URL` 并处理跨域。
- 可访问性检查 `npm run test:preview` 仍会报公共样式的颜色对比度问题，部署前建议由 UI 负责人统一修一轮。
