## 消除职责重叠

1. **用户仓库只归王鸿，点餐车仓库只归李岷鳌。** 两个 Pinia 仓库合起来满足 T6，均通过 actions 修改数据。李岷鳌的“状态管理”职责指业务点餐车，不再重复实现登录态。
2. **王鸿的个人中心不重复实现订单模块。** 概览通过 `/me/summary` 展示摘要；完整订单列表、下单与流转归李岷鳌。以后 `/center/orders` 可挂载李岷鳌的订单组件，仍由李维护该组件。
3. **移动端只复用业务动作，不复制业务规则。** 江贤松使用 `cart` 的 actions 和 `api/orders.js` 提交；商品价格、数量边界、合计与订单状态由李岷鳌维护，移动端仅负责呈现和交互。
4. **页面域 API 与公共请求层分离。** 王鸿负责 `api/auth.js` / `api/account.js`，翟毅负责 `api/dishes.js`，李岷鳌负责 `api/orders.js`；所有文件统一导入陈续文维护的 `api/http.js`，不得在页面新建 Axios 实例或硬编码接口域名。
5. **菜品管理与订单管理分离。** 翟毅只维护菜品 CRUD/上下架；李岷鳌维护商家订单状态；陈续文维护数据约束。商家身份来源于用户仓库，不能由页面下拉框伪造。
6. **公共主题与页面布局分离。** 江贤松维护 `styles/tokens.css`、`styles/global.css` 及通用 UI；王鸿维护页面目录下的 `views/auth/login.css`、`views/center/account.css`、`views/system/status.css`。路由加载对应模块样式，修改账户布局不需修改公共主题文件。修改公共 UI 的 props/emits/slot 需同步更新使用方。
7. **数据库只有一个维护人。** 新字段先提交模型约定，由陈续文合入 `db.json`；其他成员在测试中复制临时数据库，不直接修改种子数据。当前初始化提供最小可运行账户基础，后续公共文件按上述唯一负责人交接。
8. **总路由只有组长维护。** 成员提交路由路径、名称、懒加载组件、`requiresAuth`、`roles` 需求，由王鸿合入。不能各自创建第二个 router 或修改公共守卫。

## 接口与交接约定

| 边界 | 约定 |
| --- | --- |
| 用户身份 | `userStore.user` 只保存脱敏用户资料；`role` 为 `student` 或 `merchant`，由服务端返回 |
| 登录状态 | `userStore.isAuthenticated`、`login()`、`verifySession()`、`logout()`；会话过期由守卫/统一 401 事件处理 |
| 业务请求 | 统一 `http` 实例，`Authorization: Bearer <token>` 自动附加；错误交给调用方展示，不能吞掉错误返回成功 |
| 价格 | `price` 由接口约定为人民币元，业务计算先转整数分；展示统一两位小数，不用浮点金额直接累加 |
| 菜品状态 | 建议 `available` 布尔值；菜品/订单字段变更由陈续文在接口契约中确认后执行 |
| 订单状态 | `pending`（待取餐）→ `completed`（已完成）；服务端校验角色、本人/本档口范围和状态转换 |
| 空白模块 | 预约的菜单/订单路由当前只呈现明确的服务准备状态，验收表中仍记未完成；接入时替换对应入口，不复制账户模块 |
| 初始化交接 | 当前新增的工程入口、公共 UI 与 json-server 基础由组长提供可运行基线；后续按本表归属维护，其他成员必须提交本人实际开发的内容 |
